# v2 — Engenharia analítica

## Objetivo

Usar uma cópia controlada dos dados locais para aprender modelagem analítica e transformações reprodutíveis sem complicar o MVP ou enviar transações reais a uma plataforma externa.

## Stack proposta

- DuckDB local como warehouse analítico derivado; SQLite continua como armazenamento operacional da aplicação.
- dbt Core com adaptador DuckDB, executado localmente, para modelos, testes e documentação de transformação.
- Dados de entrada de treino: fixtures sintéticas por padrão. Uma cópia local de dados pessoais só pode ser usada depois de decisão explícita, fica ignorada pelo Git e não é enviada a CI.
- Databricks é opcional para objetivo educacional posterior. Antes de habilitar: verificar termos, região, limites/custos, autenticação, retenção e o conteúdo enviado. Começar apenas por dados sintéticos ou agregados e nunca por CSVs brutos.

## Sprints e TDD

1. **Contrato analítico:** definir perguntas de negócio e granularidade; teste define unicidade, chaves, sinais e datas. Construir camada analítica separada sem afetar a aplicação.
2. **Modelos dbt/DuckDB:** modelos de staging e marts mensais por pessoa/categoria; dbt tests para chaves, valores permitidos, não nulos e reconciliação de totais.
3. **Orquestração local:** executar transformações por comando ou job local idempotente; testar reexecução e falha parcial antes de automatizar.
4. **Comparação/Databricks opcional:** comparar custo operacional, aprendizagem e privacidade em um desenho documentado; só executar com ambiente e dados autorizados explicitamente.

Cada sprint tem testes escritos antes da transformação, resultados reproduzíveis e handoff próprio. O aceite de uma sprint é obrigatório para começar a próxima.

## Critérios de aceite

- Métricas analíticas reconciliam com o total operacional para o mesmo período e filtros.
- Reexecução produz o mesmo resultado e os testes dbt detectam entradas inválidas.
- Arquivos de saída analíticos, warehouse, perfis locais e dados reais ficam fora do Git.
- CI executa somente fixtures sintéticas.
- Databricks não é usado com dados pessoais sem decisão específica sobre custo e privacidade.
